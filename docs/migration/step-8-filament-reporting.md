# Step eight: Filament reporting and administrative actions

Prepared 11 October 2026 (Asia/Colombo). This is a source-only local checkpoint, not production deployment or complete security certification.

## Reporting behavior

The native owner dashboard shows all booking counts, pending/completed counts, salon count, current plan/trial expiry, remaining days and monthly request usage. Administrators see owner/pending-owner and site-visit totals in addition to subscription and booking reporting. Analytics include completed bookings, top services, salon/month breakdowns and a weighted average over individual ratings.

Booking values are estimates for approved/completed appointments at **current service prices**, including soft-deleted services. No historical price snapshot, booking payment ledger, refund ledger or cost ledger exists. The UI now labels these estimates instead of claiming collected revenue or profit. The unused hardcoded 20% commission calculation is removed; no new commission contract or actual profit calculation is introduced. All-time/selected-month totals include future confirmed appointments; period charts end today. Daily periods cover exactly 7/30/90 inclusive calendar days; 12-month charts start on the first day and avoid month-end overflow. The all-time selector's trend remains the latest 30 days, while its totals/top services cover all dates through today. Today uses appointment date rather than request creation date.

Quota usage counts requests **created** this month across all of the owner's salons, even when analytics selects one salon, matching the shared booking service. Subscription status buckets are disjoint: active now, scheduled future renewal, pending, expired, canceled and rejected. Recorded subscription payments retain active/expired/canceled history. Monthly amounts are grouped by subscription start date because the schema has no payment-received/approval timestamp; they must not be interpreted as cash receipts in that month. Imported positive amounts without qualifying paid statuses require separate reconciliation. Top packages count currently active subscriptions, excluding scheduled renewals.

Analytics recheck verified role, owner approval, active subscription and analytics entitlement on every query/update. Forged foreign salon IDs return 404 rather than silently falling back to all salons. Earliest booking-year options are scoped to authorized salons. Period, year and month updates validate and retain the last valid state on error. Charts load from a pinned root npm dependency built by Vite instead of a mutable third-party CDN script. Chart objects stay outside Alpine reactive state; registry-based cleanup prevents animations accessing destroyed canvases after Livewire filtering. The root npm audit initially reported 11 vulnerable dependencies (1 critical, 9 high, 1 moderate). Compatible updates within existing version ranges reduced the root audit to zero; root Vite now resolves to 7.3.7. This does not certify the separate retained React dependency tree or PHP dependencies.

## Packages and account actions

Package editing now has a registered route, table edit action and populated detail view. Forms use LKR, bounded nonnegative prices matching the decimal column, integer duration/limits, ordered availability dates, calendar entitlement and a typed feature list. Monthly quota remains required because the current schema does not permit NULL; adding unlimited packages needs a separately reviewed schema change. Availability dates are also enforced when creating requests/trials through the shared service, including requests that bypass the pricing page; boundary dates are inclusive. Existing pending requests retain their quoted snapshots after package edits. Current plan limits/features still follow current package settings, as before; this stage does not introduce grandfathered entitlements.

Archiving a package is blocked while pending, active or scheduled subscriptions reference it. Deactivate new purchases instead. The shared archive service locks the package; subscription requests and trial creation acquire the same package lock. Historical subscriptions load soft-deleted packages so their names/history remain visible. Restore remains administrative; permanent deletion remains prohibited. These locks are implemented but new archive/request concurrency is not yet independently load-tested on MySQL.

Native and legacy API approvals share UserModeration, which locks the target, checks the acting administrator and revalidates pending state. Only owner/customer approval roles are accepted, and approval audit fields come from the actor. The existing pro-salon 90-day onboarding trial behavior is now shared with native approval and is granted only to accounts without subscription history. Mail runs after commit; real delivery/retry remains a deployment gate. Rejection refuses approved users and accounts with salon/subscription/booking records, protecting against stale dialogs. Approval logs no longer emit the recipient's name/email. General deletion of established non-admin accounts remains a separate existing action; it is not equivalent to rejection and still needs a retention/business review.

Administrator accounts cannot be edited/deleted via user management; use native account settings for one's own profile. User creation/editing validates roles before persistence, keeps role/account writes transactional, ignores browser audit fields, records approval changes and leaves passwords empty on edit. Existing model hooks clear email verification on email changes and revoke tokens/sessions on password changes.

The unchecked Generate Subscriptions action is removed. Approval is per request with a verified payment amount. Admins can cancel active/scheduled subscriptions without deleting their recorded amount; cancellation does not record a refund. Pending requests remain editable; the subscription detail edit shortcut now reflects that rule. Owners retain their established renewal/payment-detail journey and approved renewal scheduling.

## Remaining migration gates

React source, legacy APIs/write/nested routes and their reporting endpoints are retained. Legacy analytics API calculations are not rewritten by this step and may differ from the native definitions; reconcile or retire them before final cutover. Exact React visual/chart-filter parity, visits-by-year charts, notification/WhatsApp workflows, calendar timezone/interaction comparison, media/security dependency audits, established-account retention, real mail/payment integrations, production performance/concurrency and deployment checks remain open. No new schema migrations or writes were applied to the imported MySQL database.
