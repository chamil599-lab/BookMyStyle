# Step twenty-one: browser journeys with imported records

The next local verification gate now exercises actual Chrome form login, native sessions and Blade/Filament navigation against a fresh isolated MySQL copy. All ten imported identities retain their email, roles, verification and approval state. Temporary random passwords are written directly to the copy only, without invoking password-change observers or notifications. This verifies the login flow with existing identities, not knowledge or validity of their original passwords.

```powershell
php -d memory_limit=512M scripts/migration/verify-imported-browser.php 'C:/Program Files/MySQL/MySQL Server 26.7/bin/mysqldump.exe' 'C:/Program Files/MySQL/MySQL Server 26.7/bin/mysql.exe'
node --test scripts/migration/imported-browser.test.mjs
```

Chrome is required; the optional third PHP argument selects its executable. The runner requires local loopback MySQL and a fresh private artifact directory. Backup/restore/index migration/rollback/reapplication verification is delegated to the existing guarded rehearsal. Named copy configuration strips the source connection name and verifies the schema resolver before any credential update. The HTTP worker removes every other database connection from its configuration, explicitly routes database sessions/cache/locks to the copy and uses a private cache prefix, compiled views and log directory. The parent guards source SQL and checks all-table source fingerprints, including on verification failure when the source remains readable.
