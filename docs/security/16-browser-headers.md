# 16 - Browser security headers and CSP

Checked 16 October 2026. Added missing baseline response headers. Baseline tests pass; a strict script/resource CSP remains outstanding and is not certified by this result.

Added SecurityResponseHeaders globally and to exception-response rendering so both normal Laravel responses and errors receive protection. Headers are X-Content-Type-Options: nosniff; X-Frame-Options: SAMEORIGIN; Referrer-Policy: strict-origin-when-cross-origin; Permissions-Policy disabling camera/microphone/geolocation; and X-XSS-Protection: 0 to disable legacy browser XSS filters. Existing per-response policies are preserved. Production HTTPS responses additionally receive HSTS max-age=31536000, without includeSubDomains/preload. HSTS is not emitted by this code for local environments or HTTP requests. Correct TLS/proxy detection remains a deployment requirement.

Enforced CSP currently restricts base-uri to self, object-src to none, frame-ancestors to self and form-action to self. These directives restrict base-tag abuse, plugin objects, cross-origin framing and external form submissions. They do not restrict scripts, styles, frames loaded inside the page, images or connections. Google sign-in uses a same-origin submission form; its external client script remains permitted. Current Livewire/Alpine code uses dynamic expression evaluation (including new Function in the installed Livewire bundle), and authored views have inline scripts/styles. A strict nonce/hash script policy requires compatible client code and a browser-tested rollout; silently permitting unsafe-inline/unsafe-eval would not constitute a strict policy.

Added seven cases covering public/login/panel/API-error/404 response headers, HSTS environment/protocol behavior and preservation of an existing restrictive per-response CSP. Combined with BladeAuthTest and FilamentManagementTest: **56 tests passed, 278 assertions**. Synthetic SQLite fixtures only; imported MySQL data was untouched. HTTP tests check rendering/behavior and headers, not a real browser's enforcement or live Google popup flow.

Outstanding: strict script/resource CSP and production browser verification; equivalent headers for assets/media served directly by the web server/CDN; live TLS/proxy/HSTS validation; and review of hosting-added duplicate/conflicting policies. Laravel middleware cannot add headers to files the server serves without invoking PHP. No production deployment or persistent browser HSTS change was performed by this audit.

References: [OWASP HTTP headers](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html), [OWASP CSP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html). Next category: dependencies and deployment security.
