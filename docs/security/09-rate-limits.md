# 09 - Brute-force protection and rate limits

Checked 16 October 2026. Existing login/recovery/public-write controls passed locally. Fixed missing throttling on authenticated current-password checks in the API password-change endpoint and both browser password-change and account-deletion forms. These entry points now share AuthActionLimiter's password-change bucket: five attempts per normalized email/IP pair per minute and an aggregate 30 attempts per IP per minute. Enforcement happens before password validation, including malformed attempts. The existing validation-error response is used for this shared limiter, rather than HTTP 429.

Reviewed authored route throttles, Livewire action limiters, notification actions, proxy trust, cache configuration and installed Filament authentication limits. API login permits five attempts per email/IP and 30 per IP per minute. API registration, Google and recovery share a ten-per-IP-minute bucket. Public booking/site-visit writes share ten per IP per minute. Livewire booking limits submissions to ten per IP per minute; native login, registration, recovery, confirmation, verification, reviews and favorites have action limits. Retained account/management API and browser mutations also have route limits. Installed Filament auth code limits login to five and registration/reset actions to two attempts; those Filament limits were source-reviewed, not independently load-tested in this run.

Added eight tests covering the sixth API login request, Retry-After and cooldown recovery; rotated-email attempts reaching the aggregate IP ceiling; five public API endpoint limits; and password-guessing attempts shared across browser/API changes and both deletion forms. Invalid public booking payloads exercise throttling before writes. Existing tests additionally exercise native login lockout, verification resend limits and proxy trust.

Validation: initial combined run passed **45 tests, 265 assertions** (RateLimitSecurityTest, AuthenticationSecurityTest, PasswordUpdateTest and BladeAuthTest). After extending protection to deletion forms, the final targeted run passed **21 tests, 188 assertions** (RateLimitSecurityTest, AccountDeletionTest and PasswordUpdateTest). Synthetic SQLite/cache fixtures only; imported MySQL data was untouched and no emails were sent.

Limits: these are application-level controls, not DDoS protection. Browser/API/Filament login buckets are separate; distributed attempts across many IPs are not globally account-locked. AuthActionLimiter uses check then increment, so strict concurrent request ceilings are not guaranteed. Production requires a persistent shared cache and correct trusted proxies across every application worker. Production load/concurrency, edge/WAF controls and live cache topology were not verified.

Reference: [OWASP authentication guidance](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html). Next category: file upload security.
