# 10 - File upload security

Checked 16 October 2026. Local upload validation and authorization checks passed. Hardened the active salon cover/gallery fields with 6000-by-6000 maximum dimensions, matching editorial image limits. Removed preserveFilenames from the older ManageSalonImages page so it uses Filament's generated storage names if reused; that page is not currently registered in SalonResource routes. No existing uploaded files were renamed or removed.

Reviewed API image-cycle uploads, Filament image-cycle/team/service/deal/salon upload fields, public storage settings, Spatie media handling, installed Livewire temporary-upload defaults and Apache/deployment execution restrictions. API uploads require a verified administrator and recheck current role. Raster MIME allowlists exclude SVG; API image rules inspect file content and limit dimensions and size to 10 MB. Editorial forms likewise restrict raster types, 10 MB and dimensions. Salon uploads accept JPEG/PNG/WebP, limit individual files to 1 MB and gallery count to ten, and now limit dimensions. Active forms use generated names rather than client paths. Salon media deletion callbacks scope media to the authorized salon record.

Livewire's installed defaults allow temporary files up to 12 MB, throttle temporary upload requests at 60/minute and expire upload signatures after five minutes; final field validation is a separate step. Temporary files use the configured default disk, whose source default is private local storage. Actual production disk overrides remain deployment configuration.

Extended the upload tests with oversized raster files, real PNG bytes bearing a PHP extension, customer/owner API upload attempts and Filament SVG rejection. Existing tests cover normal generated-name uploads, SVG/PHP-content spoofing, oversized dimensions, unsafe URL protocols, revoked administrator roles and native Filament persistence. Rejected payloads leave no permanent public files or database records. **31 tests passed, 150 assertions**, including UploadSecurityTest and FilamentManagementTest. The new salon dimension rules were source-reviewed; this run does not separately exercise each salon image conversion or dimension boundary.

Limits: uploaded media is intentionally public. Original raster content is not comprehensively re-encoded or antivirus-scanned; validation is not proof that every image parser payload is harmless. public/.htaccess blocks common executable upload paths, but Apache rules do not certify Nginx/Herd/cPanel execution behavior. DEPLOY_CPANEL.md requires disabling script execution in upload storage, including alias/symlink targets. Live production server rules, image-processing libraries, storage permissions and upload quotas were not verified. Synthetic SQLite and fake filesystem fixtures only; imported MySQL and existing media were untouched.

Reference: [OWASP file upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html). Next category: unsafe URLs and redirects.
