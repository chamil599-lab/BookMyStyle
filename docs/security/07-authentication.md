# 07 - Authentication security

Checked 16 October 2026. No account-takeover path was found in the reviewed flows. Fixed one request-validation gap: the API password-reset token was only required, allowing non-string input to reach the password broker. It now requires a string of at most 255 characters and returns a validation error for an array. This was input hardening, not evidence of a successful authentication bypass.

Reviewed password credentials and hashing, browser session establishment, API token issuance, Google ID-token verification and account linking, password changes/resets and signed email verification. Password login uses Laravel authentication or Hash::check; unknown email and wrong password share an API error. Password resets use Laravel's broker with 60-minute expiry, email binding and token consumption. Password changes revoke bearer tokens and rotate remember credentials via User model events. Email changes clear verification. Signed verification links bind the authenticated account ID and email hash. Existing tests cover expired, unsigned, foreign-account and stale-email links.

GoogleIdentityVerifier uses the installed official Google client with the configured client ID. Source review confirms signature validation against Google's keys, issuer checks, audience comparison and JWT expiry validation. Missing client configuration and verification exceptions fail closed. AccountService requires a verified email and subject, rejects conflicting subject/email accounts, preserves existing privileges and does not link a third-party-email password account solely on Google's email claim. Existing Google tests mock verified claims to exercise account-linking decisions; real Google sign-in and cryptographic key rotation were not tested live. See [Google's server-side ID-token validation guidance](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

Added seven cases covering credential failures without token issuance; wrong-email/invalid, expired, replayed and malformed reset tokens; bearer revocation after reset; wrong current passwords; and missing Google client configuration. Validation: the initial combined authentication run passed **53 tests, 188 assertions**. After token validation changed, all **7 focused tests passed, 24 assertions**, including the newly added malformed-token case. Across runs, 54 distinct tests were verified. Browser authentication, password reset/update/confirmation and email verification tests were included in the initial run.

Synthetic SQLite fixtures only; imported MySQL data was untouched. No real emails or Google credentials were used. MFA and production OAuth/domain/TLS configuration are outside this result. Session/cookie security and comprehensive rate-limit review remain subsequent checklist items.
